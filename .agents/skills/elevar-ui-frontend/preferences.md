# Preferencias de `elevar-ui-frontend`

Este archivo conserva preferencias confirmadas que ayudan a aplicar la skill sin transformar una decisión local en una regla de diseño universal.

## premium-minimalista-y-legible

- Regla: cuando el usuario delega una UI con ambición visual, priorizar lectura inmediata, jerarquía clara, copy persistente contenido, espacio con propósito y detalles deliberados. `Premium` no equivale a añadir decoración; cada elemento debe justificar su presencia.
- Cuando aplica: pantallas, menús, dashboards, informes, modales y componentes donde se pida mejorar la estética, conseguir un resultado distintivo o reducir supervisión visual.
- Ejemplo: destacar la acción o dato que guía la decisión y dejar ayuda secundaria bajo demanda puede ser preferible a dar el mismo peso a todas las superficies y explicaciones.
- Advertencia: no reducir contexto, ayuda o densidad por estética cuando ocultaría una decisión difícil, una consecuencia relevante, una obligación o información necesaria para operar con seguridad.
- Última confirmación: 2026-07-21

## one-shot-visible-multipaso-interno

- Regla: preferir una entrega visual única al usuario después de formular una hipótesis, renderizar, criticar y corregir internamente; no pedirle que dirija microdecisiones que puedan resolverse con el design system, referencias y criterio profesional.
- Cuando aplica: UI nueva, reestructuración relevante o petición explícita de acabado distintivo. No aplica a microajustes locales que no cambian lectura, jerarquía, estado ni responsive.
- Ejemplo: comparar internamente una captura con el claim perceptivo y corregir agrupación o densidad antes de mostrar el resultado por primera vez.
- Advertencia: el one-shot no sustituye el feedback humano cuando la decisión de producto es material, faltan datos esenciales o no hay evidencia visual suficiente para sostener el resultado.
- Última confirmación: 2026-07-21
